【scoring.rs 三处根因 · 按 issue 原文逐行】
1) src/pipeline/steps/scoring.rs:17
   `let max_similarity = scores.first().map(|s| s.combined_score).unwrap_or(0.0);`
   —— 空检索把「没查」当「查了且完全不相似」。改成显式分支：scores 为空直接走「证据不足」路径，不进加减公式。
2) src/pipeline/steps/scoring.rs:31-34
   `let coverage_gap_bonus = if ctx.diversity_score < 0.5 { (1.0 - ctx.diversity_score) * 8.0 } else { 0.0 };`
   —— 覆盖越差加分越多；quick 模式 diversity_score 恒为默认 0.0 ⇒ coverage_gap_bonus 恒 +8。把 diversity_score 改成 Option<f64>，DiversityGate 被跳过时是 None，None 时 bonus 必须为 0；禁止用 0.0 同时表达「实测多样性 0」和「没测」。
3) src/pipeline/steps/scoring.rs:43-46
   `let raw_score = 100.0 - max_sim_penalty - avg_penalty + contradiction_bonus + coverage_gap_bonus; let final_score = raw_score.clamp(0.0, 100.0);`
   —— 空证据 raw=108 被 clamp 压回 100，掩盖「分数可超界＝靠加分凑」的信号。加 `debug_assert!(raw_score <= 100.0)`，让越界在开发期炸出，不许静默压成满分。

（第 4 处因果在 src/pipeline/state.rs:116-127 与 src/pipeline/context.rs:357：quick 跳过 DiversityGate/DetectContradictions 使 diversity_score 保持默认；若引入 Option 波及这两处，按 issue「修复方向」处理。）

【证据不足语义】novelty_score 返回 null（或引入 status:"insufficient_evidence"），报告文案改为「未获得任何对比文献：本地库 0 条 / 在线搜索未配置，无法评估新颖性」，并给可操作出路（导入文献、配 SerpAPI/EPO）。
