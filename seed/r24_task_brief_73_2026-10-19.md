【必读·不凭记忆】issue #73 全文：https://github.com/jsshwqz/innoforge/issues/73
两处崩溃点：
1) `src/routes/settings.rs` 的 `mask_api_key` 用 `&key[..4]` / `&key[key.len()-4..]` 按字节切——非 ASCII 且 >8 字节的 Key 会 panic（`byte index 4 is not a char boundary`），`GET /api/settings` 直接断连（HTTP 000）。
2) `src/experiment/sandbox.rs` 的本地 `truncate` 用 `&s[..max]` 切字节，中文超过阈值（5000/2000）几乎必然 panic。
3) 同病根但没爆：`/api/settings/ai` 只校验 `api_key.len()`（字节），不校验字符集，所以 `"测试密钥"`（9 字节）能存进库，然后读取时崩。

【要改的五件事·按 issue 原文】
1) `mask_api_key` 改为按**字符**取前/后各 4 个（`chars().take(4)` / `chars().rev().take(4).rev()` 或等价实现），任何非 ASCII 输入都不得 panic；ASCII 输出形态必须保持 `sk-a****5678`，`len<=8` 仍回显 `****`。
2) `/api/settings/ai` 入口校验 Key 字符集：只允许可见 ASCII（0x21..=0x7E），不含空白/控制字符；非法返回 **4xx + 明确原因**，**不得落库**。与 EPO 通道 `parse_epo_credential` 的既有判据保持同一把尺子（先读那段代码）。
3) `sandbox.rs` 删除本地 `truncate`，统一改用 `crate::ai::client::safe_truncate`（必要时加上 `...(truncated)` 后缀，保持输出语义）；同类局部实现一并收编，避免再分叉。
4) 全仓加一条防线：静态检查或测试，禁止新增「`&s[..n]` 且 n 未做 `is_char_boundary` 回退」的写法；若不便静态化，至少在 `AGENTS.md`/review 清单写明（仓库若有 `docs/` 下的约定文档，放那里更合适）。
5) 测试要覆盖恢复性：先存坏 Key（4xx），再存合法 ASCII Key（200），随后 `GET /api/settings` 必须 200。

【测试红线·双向负控】
- 正向A：`POST /api/settings/ai` 传 `"测试密钥"` ⇒ 4xx + 说明；紧接着 `GET /api/settings` ⇒ 200。改前必红（200 + 000）。
- 正向B：sandbox truncate 输入 40 个汉字、max=10 与 max=5000 ⇒ 不 panic，结果前缀是合法 UTF-8（末尾落在字符边界）。
- 负控1（不许把功能修死）：ASCII Key `sk-abcdefgh12345678` ⇒ `sk-a****5678`；≤8 字符短 Key ⇒ `****`；SerpAPI/EPO 掩码回显形态不变。
- 负控2：把 `mask_api_key` 改回 `&key[..4]` ⇒「中文 Key 不走 200 且 GET 保持 200」那条必须红；跑完改回。
- 恢复性：坏 Key 被拒后，用合法 Key 覆盖 ⇒ `GET /api/settings` 200。
