【必读·不凭记忆】issue #72 全文：https://github.com/jsshwqz/innoforge/issues/72
核心：`src/db/relevance.rs` 的 `is_chinese_name` / `is_likely_name` 用 `q.len()`（UTF-8 字节）判「2–6 字姓名」，2 个汉字=6 字节恰好落进姓名区间 ⇒ 两字技术词（相变、石蜡、齿轮…）被判成发明人，只查 inventor 列 ⇒ 0 命中且 `search_type:"inventor"`。另 `src/db/patent.rs:585` 多词查询整串塞进一个 `%…%` LIKE（含空格），两词都命中合起来也 0。

【要改的四件事·按 issue 原文】
1) **字符数而非字节数**：`is_likely_name` / `is_chinese_name` 的边界一律 `chars().count()`；姓名判据必须真正依赖**姓氏表或「姓+名」结构**，不许「短且纯中文」即算姓名（同模块 `src/db/patent.rs:120-121` 已有正确写法可参照）。
2) **多词语义显式化**：按空白切 token，明确选 AND（每个 token 命中任一字段，全部 token 命中才返回）或 OR（按命中数排序），选一种并把语义写进 `docs/`（`docs/errors.md` 条目 + 相关 API 文档），不许停在隐式整句 LIKE。
3) **响应可自证**：保留 `search_type`；新增 `matched_fields` / `applied_filter`（命名自定但要一致），让调用方看得出「这次只查了 inventor 列」。
4) **0 命中有原因**：返回原因字段（库中无该词 / 查询被判为发明人检索 / 多词 AND 无交集），可与 #67 的 hint 合成一个字段。
