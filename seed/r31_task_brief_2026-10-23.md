## #83 — 证据不足文案：区分"未配置 Key"与"配了但 0 结果"（当前是假原因）

**现状（精确锚点，`src/routes/search.rs`）**：面向用户的"未配置"文案有两串字面量——`"未配置 SERPAPI_KEY，本轮未发起在线请求"`（≈:46 与 ≈:1748）与 `"未配置有效 SerpAPI Key，已自动尝试下游回退。"`（≈:746，经 `serpapi_skipped_outcome`）。链路在 `≈:745 if api_key_opt.is_none()` 才该记 `未配置`（这一段本身对）。问题是**当 Key 已配置（`api_key_opt.is_some()`）但在线三源真实跑完、0 命中**时，某处仍复用/落到了"未配置"类 `error`/`hint` 文案，给用户造成"你没配 Key"的假原因（issue 标题：3 处拷贝）。

**要做**：
1. 全仓审计所有把"没跑成"归因到"未配置 SERPAPI/Key"的用户可见文案（`src/routes/search.rs` 为主，连带 provider 回退路径与任何 `error`/`hint` 组装点），确保**只有 `api_key_opt.is_none()`（真未配置）才出现"未配置"字样**。
2. 区分成**三态**并可测：
   - `not_configured`：没配 Key（现有"未配置…回退"文案，保持不变以不破坏既有 attempts 约定）。
   - `configured_no_results`：配了 Key、真实发起了在线请求但 0 命中 ⇒ 新文案（如"已发起在线搜索但无结果 / configured but returned no results"），**绝不含"未配置"字样**。
   - `error`：网络/配额/鉴权失败（已有 `HTTP <code>`/认证类）。
3. 不改 `attempts` 既有键的"空与非空两态逐字一致"契约（MA5b 有测试锁死前端面板字面量），只新增/更正"配了但 0 结果"这一态的 `source`/`error`/`hint` 取值；改动前先看 `attempts_json_locks_frontend_panel_literals` 之类锁，别把它改红。

## #82 — e2e 失败路径不回收子进程（实测孤儿 innoforge-server，端口 7631）

**现状（精确）**：`tests/common/mod.rs::spawn_test_server` 在 `≈:160` `let child = cmd.spawn().expect(...)` 之后、到 `≈:166` 构造 `TestServer{child,…}`（其 `Drop` 会 kill+wait）之前，有一道 `≈:161 assert!(wait_for_server(port,60), …)`。若被测服务**没能在 60s 内 ready**（或该区间任何 panic/early-return），此时 `child` 还是裸 `std::process::Child`（标准库对 Child **默认不 kill**），一旦 assert 失败/panic 直接丢弃 ⇒ **子进程泄漏成孤儿**（issue 实测端口 7631 上残留 `innoforge-server`）。另有 `≈:52` 一处模板用的裸 `Command::new(...).spawn()` 同样不在守护下。

**要做**：
1. 把 `spawn_test_server` 改成**任何路径都不泄漏**：`spawn()` 成功后立刻把 `child` 纳入 RAII 守护（或先 `kill+wait` 再 panic），保证 ready 失败/超时时子进程被回收；成功路径仍返回带 `Drop` 的 `TestServer`。
2. `≈:40-57` 的裸 spawn 模板函数同样纳入守护/回收。
3. 保持对外签名不变（返回 `TestServer`），别影响现有所有 `spawn_test_server` 调用点。

**验收（双向负控）**：
- **关键（上一轮踩坑）**：测试必须让"没 kill 的孤儿"**真的可观测**。上版失败原因：用 `0s 超时` 触发 ready 失败后 panic，但 `spawn_test_server` 里的 `home = fresh_db_dir()`（`TempDir`）也随 panic 一起 drop、删掉了服务器的 `INNOFORGE_HOME`，于是**无论杀不杀子进程，孤儿都会因 home 被删而自崩** ⇒ 测试恒真、删 `kill_server(child)` 仍 2 passed。
- **正（要这么设计）**：给被测失败路径用一个**在 panic 后仍然存在的持久 home**（例如把 `TempDir` `mem::forget` 掉或用固定临时目录，使 home 不被 drop），让**未被 kill 的孤儿子进程能够继续启动并最终 bind 目标端口**。这样：修复态（kill 后）端口始终无人 bind ⇒ 断言"connect 持续失败/无监听"通过；泄漏态（不 kill）孤儿会 bind ⇒ 用例红。断言里可保留对子进程存活/port 可连的轮询（带超时）。
- 负-A：把修复的 `kill_server(child)` 删除（只 panic 不回收）⇒ **用例必红**（这是本轮验收硬标准；做不到就不算合格）。
- 负-B：仅加注释不改逻辑 ⇒ 红。
- 测试文件：新增 `tests/issue_82_no_orphan_on_failure.rs`（进程内，bind(0) 选端口，不写死；用可配短超时 helper `spawn_test_server_with_timeout`，并保持对外 `spawn_test_server` 签名不变）。
