## #88 — `/api/oa/history/detail/:id` 接错 handler

**现状（精确）**：`src/common.rs:566-569`
```
.route("/api/oa/history/detail/:id", get(routes::api_oa_history_all))
```
把"按 id 查单条"路由接到了列表 handler `api_oa_history_all`，`:id` 被完全忽略——任意 id（含不存在的）都返回**全部**历史。

**要做**：
1. 新增/改用按 id 取单条的 handler（记为 `api_oa_history_detail`），用路径里的 `:id` 查该条记录并返回；路由 `src/common.rs` 指向它。
2. 响应契约：命中返回该单条；**未命中（不存在的 id）不得回落为全部**——返回明确的未命中结果（如 `{ "found": false }` + 非 2xx，或既有代码库的 not-found 约定，二选一并说明）。参考同文件里 `api_oa_history` / `api_oa_history_delete` 既有的按参数查库与错误写法，保持风格一致。
3. 若已有可复用的"按 id 取一条"的数据访问函数，优先复用，勿重复实现 SQL。

**验收（双向负控）**：
- 正：请求存在 id=X ⇒ 返回且仅返回该条（不回全部）；请求不存在 id=Z ⇒ `found:false`/not-found，**返回体不含全量列表**。
- 负-A：把路由退回 `api_oa_history_all` ⇒ 存在 id 的用例应红（返回了全部而非单条）。
- 负-B：若 handler 对未知 id 返回全部 ⇒ "不存在 id 不回全部"用例应红。
- 新增集成测试文件 `tests/issue_88_oa_history_detail.rs`（进程内 stub 或既有测试基建风格，端口用 `TcpListener::bind("127.0.0.1:0")`，勿写死端口/勿依赖 python3）。

## #108 — `db_path_resolution::platform_data_dir_used_when_no_env_vars` 把 Linux XDG 写死

**现状（精确）**：`tests/db_path_resolution.rs:100-123` 仅设置 `HOME` 后断言 `resolve_db_path()` == `HOME/.local/share/innoforge/innoforge.db`。这是 Linux XDG 路径；Windows 上 `platform_data_dir()`（`src/common.rs:141`）返回 `%APPDATA%\innoforge`，测试必红。等于把"平台数据目录"的**某一种实现**当成普适期望。

**要做**：
- 改为按**实际平台行为**断言，Linux 与 Windows 都能真验，且不再是"只认 XDG"：
  - 用被测代码真实的解析结果作为期望：优先 `dirs::data_dir()`（或 `platform_data_dir()` 内部所用来源）+ `innoforge/innoforge.db` 拼接，与实现同源；
  - 或用 `#[cfg(target_os=...)]` 分支分别断言 Linux=XDG、Windows=`%APPDATA%`，两者都真验证；
  - 断言仍须"未设 INNOFORGE_DB/INNOFORGE_HOME 时落在平台数据目录下、绝对路径、含 `innoforge`"这些通用性质。
- 目标是**去掉把 Linux 路径当通用的硬编码**，而不是简单 skip 掉 Windows（skip 不算真验）。

**验收（双向负控）**：
- 正：Linux 与 Windows 上本用例都通过，且确实验证了"落到本应落到的平台目录"。
- 负-A：临时把实现里"平台目录"来源改错（例如 Windows 分支返回 XDG 形状）⇒ 用例应红（证明它真的在校验平台相关路径，而非永真断言）。
- 负-B：若只是加 `#[cfg(windows)] return;`（跳过）⇒ 视为**未达成**（没在 Windows 真验），要求改为真实分支断言。
- 若需要，`platform_data_dir_is_absolute_and_contains_innoforge` 之类相邻用例同步核对，别引入新写死。

## #109 — `issue_17` 拿编译期 commit 与运行时 HEAD 相比

**现状（精确）**：`tests/issue_17_synthetic_fixtures.rs:180-193` 断言接口返回的 `git_commit` == `$(git rev-parse HEAD)` 的**运行时**值。但 `git_commit` 是 `build.rs` 在**构建期**烤进去的 `GIT_COMMIT`（`build.rs:50 cargo:rustc-env=GIT_COMMIT=`）。构建与运行之间只要有任何一次 commit（例如 CI 复跑、本机在跑测中途 push），两者不等 ⇒ **假红**（本批 #109 就是这么被触发的，已在 issue 如实归因）。

**要做**：
- 把断言从"等于运行时 HEAD"改为"验证构建信息注入**生效**"，不依赖当前 HEAD：
  - 断言 `git_commit` 是非空、且为合法 commit 形状（如 40 位 hex / 或 7 位短 sha，按实现口径），即"注入确实写进了二进制"；
  - 若代码里能拿到构建期常量（`env!("GIT_COMMIT")` 同源），与接口返回值比对（同源恒等），而不是与 `git rev-parse HEAD` 比对；
  - 保留对 `/api/.../about`（或对应健康/版本端点）其余字段的断言。
- 目标：**去掉对"运行那一刻工作树 HEAD"的耦合**，只测"构建信息被正确注入并通过接口暴露"这一真实属性。

**验收（双向负控）**：
- 正：构建后无论工作树是否有新 commit，用例都稳定通过（可在 build 之后再 `git commit --allow-empty` 一个临时 commit，重跑该用例仍绿 ⇒ 证明与 HEAD 解耦）。
- 负-A：把接口/实现里 `git_commit` 注入置空或改成非 hex ⇒ 用例应红（证明真的在校验注入形状）。
- 负-B：若只是 `#[ignore]` 掉或删除该断言 ⇒ 视为**未达成**（没验证注入），要求改为构建期同源比对。
