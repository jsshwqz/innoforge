### 2.1 UA1 公开号正则模式（执行棒可按实测样本微调，但须覆盖以下格式）

**公开号正则**（国际通用，按前缀分流）：

| 前缀 | 正则 | 示例 | 说明 |
|------|------|------|------|
| CN | `CN\d{8,12}[A-Z]\d?` | CN113224379A, CN2010100012345B1 | 中国专利公开/公告号，末尾字母为种类码（A=公开, B=公告, U=实用新型, C=PCT），可选数字为修订序号 |
| US | `US\d{6,12}[A-Z]\d?` | US20210345678A1, US1234567B2 | 美国专利，含申请公开（A1/A2）与授权（B1/B2） |
| EP | `EP\d{6,8}[A-Z]\d?` | EP3445287B1, EP1234567A2 | 欧洲专利 |
| JP | `JP\d{4,8}[A-Z]` | JP2020123456A, JP5678900B | 日本专利（特开/特许/特表） |
| KR | `KR\d{6,10}[A-Z]` | KR102345678B1, KR20210012345A | 韩国专利 |
| WO | `WO\d{4}/\d{4,6}[A-Z]\d?` | WO2021/123456A1, WO2019/023456A2 | PCT 国际申请 |

**OA 文本中常见引出语模式**（用于定位公开号上下文，区分对比文件 vs 背景引用）：

```
对比文件[1-9][:：]\s*<公开号>
引证文献[1-9][:：]\s*<公开号>
D[1-9][:：]\s*<公开号>
参考文献[1-9][:：]\s*<公开号>
```

**抽取逻辑**：
1. 对 OA 全文跑上述正则，取所有匹配；
2. 仅保留出现在「引出语模式」上下文 ±50 字符内的匹配为对比文件（排除正文偶然出现的公开号）；
3. 按出现顺序编号 D1, D2, …；
4. 与用户手贴的 `references[]` 做去重：同公开号以手贴内容为准（手贴可能含用户标注/批注）；
5. 对每个抽取到的公开号，走 `search/chain` 查询 → `routes/patent.rs:221` enrich-free 抓全文；
6. 抓取结果按 M-B §5.3 `reason_code` 枚举标注：`success` / `not_found` / `cooldown` / `rate_limited` / `parse_error` / `network_error`。

### 2.2 UA2 复审请求书结构与提交前清单详文

**复审请求书四部分结构**（`reject_review` 专用，替换现有意见陈述书模板）：

```
一、复审请求范围
  — 明确请求复审的申请号、发明名称、驳回决定发文日
  — 明确请求复审的范围（全部驳回 / 部分驳回指定权项）

二、针对驳回决定各项理由的逐项消除缺陷论证
  — 逐条引用驳回决定的理由编号，针对每条理由：
    (a) 概述驳回理由核心
    (b) 陈述消除该缺陷的具体论证（引用区别特征、技术效果、法条适用）
    (c) 如涉及修改，说明修改内容与修改依据
  — 每条论证须带出处锚点（§2.6）

三、修改文件对照说明（如有修改）
  — 修改前/修改后对照表（权项号、原文字段、修改后字段、修改理由）
  — 修改不超出原说明书与权利要求书记载的范围（A33 自检，§2.3）

四、结论
  — 请求复审委员会撤销驳回决定
  — 请求进行前置审查（如适用）
```

**提交前清单**（文末固定段，**静态结构化文案，不由 AI 即兴生成**）：

```
【提交前清单 · 请逐项确认】

□ 1. 申请号与发明名称已核对，与驳回决定载明一致
□ 2. 复审请求期限确认：自驳回决定送达之日起三个月内提出（请核实实际送达日）
□ 3. 复审官费已缴纳（当前标准：发明专利复审费 1000 元，请以国家知识产权局最新公告为准）
□ 4. 提交渠道确认：通过专利业务办理系统电子提交或面交至国家知识产权局
□ 5. 前置审查提示：复审委员会可先将本案交原审查部门进行前置审查，原审查部门同意撤销驳回的，复审委员会可不再审查
□ 6. 修改文件清单（如有修改）：修改后权利要求书 / 修改后说明书 / 修改替换页已备齐
□ 7. 附件清单：驳回决定复印件 / 原审查档案 / 证据材料（如有）
□ 8. 全部事实断言出处已核对（见出处对照表）
```

> **纪律**：清单段在 prompt 中以固定字符串注入，不经过 AI 生成环节。执行棒在 `generate_response_letter_stream` 中于 AI 输出后拼接此段，确保不漂移。

### 2.3 UA3 A33 结构化标记键格式

**出参新增键**（在分析/讨论/生成链路的出参 JSON 中追加，沿 M-B §5.1「发键不发散文」纪律）：

```json
{
  "a33_check": {
    "status": "pass | warning | risk",
    "items": [
      {
        "claim_num": "1",
        "modified_text": "一种...，其特征在于...",
        "introduced_terms": ["术语A", "术语B"],
        "original_spec_coverage": "术语A: 说明书第3段第2行 / 术语B: 未在原说明书与权利要求书中发现",
        "risk_level": "high | medium | none",
        "detail": "权项1引入「术语B」未见于原说明书第1-15段及原权利要求书，可能违反专利法第33条"
      }
    ]
  }
}
```

**判定逻辑**：
- `risk_level: high` — 修改后权项引入了原说明书和原权利要求书中均未出现的术语/特征
- `risk_level: medium` — 术语出现在原说明书但表述形式有实质差异（如范围扩大）
- `risk_level: none` — 修改仅删除/合并既有权项，或引入的术语在原说明书中有完全相同的文字记载
- `status: pass` — 所有 items 的 risk_level 均为 none
- `status: warning` — 存在 medium 级风险
- `status: risk` — 存在 high 级风险

### 2.4 UA4 refs 5000 截断二选一处置

**现状**：`src/ai/patent.rs:202` `safe_truncate(references_info, 5000)`（shallow 档）

| 选项 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **A（推荐）** | 替换为 `ai::client::truncate_for_ai(references_info, 5000)`，该函数在截断时追加数据完整性尾注 `[...已截断，原始长度 N 字符，完整内容见 references 字段]` | 改动最小（一行函数替换）；AI 知道数据被截断可主动声明；沿 AGENTS §2.5 既有工具 | AI 仍只看到前 5000 字符，深层对比文件内容可能丢失 |
| B | 不截断，若 `references_info.len() > 5000` 则在出参中返回结构化容量警告 `{"refs_truncated": false, "refs_length": N, "warning": "对比文件总量超过浅档上限，建议切换深度模式"}`，浅档不喂 refs 给 AI | 浅档不丢数据完整性；用户被明确告知需切深度模式 | 浅档分析质量可能下降（无对比文件信息）；需改出参形状 |

**推荐选 A**：改动面最小，且 shallow 档本就是快速预览，深度档（`:245` 的 300000 上限）已覆盖全文场景。执行棒须在 PR body 说明所选选项与理由。

### 2.5 UA5 六角度固定标题与输出格式

**六角度各自独立成节，标题固定（可测试）**：

| 角度序号 | 固定节标题（精确匹配） | 输出内容要求 |
|----------|----------------------|-------------|
| ① | `## 一、事实对照` | 驳回决定逐段拆解 + 权利要求逐项特征矩阵 + 「对比文件哪段公开/未公开哪个特征」映射表（表格形式：权项特征 × D1/D2/… × 公开/未公开/部分公开） |
| ② | `## 二、法条适用` | 引用法条与三步法每一步逐一验真：步骤1（确定最接近现有技术）、步骤2（确定区别特征与实际解决的技术问题）、步骤3（判断显而易见性），每步须有结论（成立/不成立/部分成立） |
| ③ | `## 三、技术效果` | 区别特征带来的技术效果逐条列举，每条须标注「原说明书是否记载该效果」（是/否+段落号），效果论证须与驳回决定认定的效果做对比 |
| ④ | `## 四、策略权衡树` | 至少给出两条论证路径（主路径 + 备选路径），每条标注：胜率评估（高/中/低）、风险点、依赖前提；路径间标注「若主路径不成立则转备选」的衔接关系 |
| ⑤ | `## 五、程序适配` | 复审程序与实审程序的关键差异说明（举证责任、审查范围、前置审查可能性），本案在复审程序中的特殊注意事项 |
| ⑥ | `## 六、说服结构` | 论证编排建议（先攻哪条理由、后攻哪条、修改与论证如何配合），含「预判合议组质疑」子段：列出 2-3 个合议组可能提出的质疑，每个质疑给出预先回应 |

**prompt 注入方式**：在 `build_reject_review_prompt` 中以固定字符串注入六角度标题骨架 + 每角度的内容要求说明，AI 在骨架内填充。禁止 AI 自行改变标题或合并角度。

**「预判合议组质疑」子结构**（角度⑥内）：

```
### 预判合议组质疑
1. [质疑内容] → [预先回应]
2. [质疑内容] → [预先回应]
3. [质疑内容] → [预先回应]
```

### 2.6 UA6 出处锚点格式与合法类型枚举

**锚点格式**：

```
【依据：<出处类型>：<定位信息>】
```

**合法出处类型完整枚举**（执行棒在 prompt 中注入此表，AI 须从中选择，禁止自造类型）：

| 出处类型 | 定位信息格式 | 示例 | 说明 |
|----------|-------------|------|------|
| `驳回决定` | 第X段 / 第X页第X段 | `【依据：驳回决定：第3段】` | 驳回决定正文 |
| `权利要求` | 权项X / 权项X第X特征 | `【依据：权利要求：权项1】` | 原权利要求书 |
| `说明书` | 第X段 / 第X段第X行 / 第X页 | `【依据：说明书：第5段】` | 原说明书 |
| `说明书附图` | 图X / 图X中标记Y | `【依据：说明书附图：图2中标记21】` | 原说明书附图 |
| `对比文件` | DX第X段 / DX第X页 / DX权利要求X | `【依据：对比文件：D1第4段】` | 对比文件全文（UA1 抓取或用户手贴） |
| `法条` | 专利法第X条 / 审查指南第X章第X节 | `【依据：法条：专利法第22条第3款】` | 法律法规 |
| `审查指南` | 第X部分第X章第X节 | `【依据：审查指南：第二部分第四章第3.2.1节】` | 专利审查指南 |

**边界规则**：
- **AI 自身的推理/分析不是合法出处**——「根据以上分析可知…」类断言须追溯到具体材料出处，否则降级为【需申请人确认】或删除。
- **用户讨论中的陈述不是合法出处**——讨论内容是辅助输入，不是可引用的事实来源。
- **无法定位到具体段落的笼统引用禁止使用**——「说明书多处记载」「对比文件整体公开」不合规，须定位到具体段落/页码。
- **出处对照表**（输出末尾固定段）：

```
## 出处对照表
| 序号 | 断言摘要 | 出处类型 | 定位信息 |
|------|---------|---------|---------|
| 1    | D1公开了特征X | 对比文件 | D1第4段第2行 |
| 2    | 区别特征带来效果Y | 说明书 | 第5段 |
| ...  | ...     | ...     | ...     |
```

> **执行棒实现路径**：在 `build_reject_review_prompt` 与 `generate_response_letter_stream` 的 prompt 中注入锚点格式说明 + 合法类型表 + 边界规则；在 `fact_check` 中新增「无出处断言检测」：扫描输出中的事实断言（启发式：含「公开了」「记载了」「显示了」「指出」等事实动词且未跟 `【依据：…】` 的句子），标记为 `missing_source` 警告。

## 3 不做

- 不做专利有效性电子化提交（只生成文书，不接官方 API）。
- 不做对比文件全文翻译（抓到的外文全文原样注入，翻译由 AI 在分析中自行处理）。
- 不做「复审成功率预测」——对外口径沿 §0.4，禁止任何成功率承诺。
- 不做新 UI 页面——复用现有 OA 三环节页面，改动仅限 `getRefs()` 逻辑 + 答复书渲染。

## 7 实现顺序与依赖

**UA 间依赖关系**：

```
UA4（refs 截断销账）        ← 无依赖，独立改一行函数
UA1（对比文件自动抓取）     ← 无依赖，但 UA4 先做可确保 refs 质量更好
UA6（出处锚点纪律）         ← 无依赖，但 UA1 先做可提供更多可引用出处
UA3（A33 对照自检）         ← 无依赖，独立新增检查环节
UA5（六角度框架）           ← 依赖 UA6（六角度内容须带出处锚点）
UA2（复审请求书模板）       ← 依赖 UA5（答复书内容基于六角度分析输出）
                           ← 依赖 UA3（修改文件对照说明须含 A33 自检结果）
                           ← 依赖 UA6（论证须带出处锚点）
```

**推荐实现顺序**（最小化上下文切换，先独立项再依赖项）：

| 序 | UA | 理由 | 预估改动面 |
|----|-----|------|-----------|
| 1 | UA4 | 一行函数替换，最快出活，建立信心 | `patent.rs` 1 行 + 用例 |
| 2 | UA3 | 独立新增检查，不改既有流 | `fact_check.rs` 新增函数 + 出参键 + 用例 |
| 3 | UA1 | 独立新增抽取逻辑，前端 `getRefs()` 小改 | `patent.rs` 新增正则抽取 + `search/chain` 复用 + 前端小改 + 用例 |
| 4 | UA6 | prompt 注入 + `fact_check` 新增无出处检测 | `patent.rs` prompt 改 + `fact_check.rs` 新增检测 + 用例 |
| 5 | UA5 | prompt 骨架改，依赖 UA6 锚点纪律已就位 | `patent.rs` `build_reject_review_prompt` 改 + 用例 |
| 6 | UA2 | 模板改 + 清单拼接，依赖 UA5/UA3/UA6 已就位 | `patent.rs` `generate_response_letter_stream` 改 + 用例 |

> **每项完成后跑对应验收用例（§4），全绿后再进下一项。** 如某项发现需改超出预估范围，暂停并报告规划会话。

## 8 风险与缓解

| # | 风险 | 影响 | 缓解 |
|---|------|------|------|
| R1 | UA1 正则在实测 OA 样本上漏匹配（OA 格式多样：表格、编号不连续、繁简混排） | 对比文件未自动抓取，用户需手贴 | 执行棒开工前收集 ≥3 份真实 OA 样本跑正则验证；漏匹配的格式补正则并在 PR body 记录；**手贴优先级始终保留作为兜底** |
| R2 | UA1 对比文件全文抓取触发反爬/限流 | 抓取失败 | 沿 `breaker` 既有冷却纪律；失败如实标 `reason_code`，不阻塞分析流程（降级为「对比文件未获取，请手贴」） |
| R3 | UA2 复审请求书模板改动影响 `first_exam`/`abnormal` 路径 | 非复审流程回退 | 模板按 `oa_type` 分流，非 `reject_review` 走原模板；V7 回归用例锁 |

| R5 | UA6 出处锚点检测误报（把非事实断言标为 missing_source） | 输出噪音 | 启发式事实动词列表收窄（仅「公开了」「记载了」「显示了」「指出」「披露了」等强事实动词）；误报降级为 warning 不阻塞输出；执行棒用例覆盖正例/反例 |
