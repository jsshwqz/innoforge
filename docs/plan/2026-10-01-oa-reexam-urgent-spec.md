## 2 范围（六项，全部围绕复审任务，禁止顺手扩面）

| # | 项 | 内容 | 锚点 |
|---|---|---|---|
| UA1 | 对比文件自动抓取 | 从 OA 文本抽取对比文件公开号（正则执行棒按实测 OA 样本定，注意 CN10xxx / US / EP 前缀与 A/B/U 后缀）→ 复用既有 `search/chain` 查询与 `routes/patent.rs` enrich-free 全文抓取 → 组装 `references[]` 注入分析请求。**用户手工粘贴的内容优先级更高**（同号去重以手贴为准）；抓取失败在出参如实标注 `reason_code`（沿 M-B §5.3 枚举，禁止把「没抓到」写成「无对比文件」） | §1.2 |
| UA2 | 生成答复书复审模板（**终稿形态**） | `generate_response_letter_stream` 按 `oa_type` 分模板：`reject_review` 走复审请求书结构（① 复审请求范围；② 针对驳回决定各项理由逐项消除缺陷论证；③ 修改文件对照说明（如有）；④ 结论），沿用【需申请人确认】反编造纪律；**产出按可直接抄入官方复审请求书理由栏的成稿为靶**，文末固定附「提交前清单」段（程序性固定文案：申请号与期限起算日提醒、复审官费金额提醒、提交渠道提示、前置审查会先由原审查部门复查的提示——此段为静态结构化文案，不由 AI 即兴生成）；`first_exam`/`abnormal` 模板行为不变（出参/语义零回退） | §1.4 |
| UA3 | A33 对照自检强化 | 在讨论/生成链路加入「修改后权项 vs 原权利要求书 + 说明书公开内容」显式对照步骤，超范围风险出**结构化标记键**（M-B §5.1 纪律：发键不发散文），并保留/强化 `fact_check.rs:606` 既有术语检查 | §1.5 |
| UA4 | refs 5000 截断销账 | §1.3 二选一处置 + 用例锁 | §1.3 |
| UA5 | 分析端「六角度」结构化框架 | `build_reject_review_prompt`（及 deep 档）强制按六角度输出，治「单轮生成覆盖面靠运气」：① **事实对照**——驳回决定逐段拆解 + 权利要求逐项特征矩阵 + 「对比文件哪段公开/未公开哪个特征」映射表；② **法条适用**——引用法条与三步法每一步逐一验真；③ **技术效果**——区别特征带来的实际效果 + 本领域技术人员视角反证「技术启示」不成立；④ **策略权衡树**——争辩 vs 修改（含从属权项上升退路）逐分支列利弊，**只列不选**（选择权留给申请人）；⑤ **程序适配**——复审请求范围 / 前置审查 / A33 修改红线核对；⑥ **说服结构**——文书组织与语气，含**预判合议组质疑并预先回应**（每个主论点后附「可能被如何反驳 + 回应」）。六角度各自独立成节，标题固定（可测试） | 本文件新立；现状分析为单轮自由生成，无强制角度骨架 |
| UA6 | **出处锚点纪律（零幻觉可审计）** | 分析与答复书中的**事实断言必须带出处锚点**：`【依据：驳回决定第X段｜权利要求X｜说明书第X段｜D1第X段】` 格式（执行棒可按实测样本微调格式，但锚点必须指向用户提供的材料内部，禁止指向不存在的段号）；输出末尾附**「出处对照表」**节（断言 ↔ 出处逐行列出）；**无法从材料溯源的断言禁止写入**（删掉或降级为【需申请人确认】，沿 `fact_check` 既有防线扩展，禁止新造平行机制）。这是用户拍板的「零幻觉」标准：真实性成为可审计属性，不靠模型自觉。**范围（v2 收窄）**：MB4 已在 pipeline 决策建议段交付出处标注，UA6 限 **OA 分析/答复书链路**，与其互补不重复 | 本文件新立；现状 `check_oa_analysis` 只做术语/编造核查，无逐断言出处纪律 |

## 4 验收（无 Key 环境可闭环 + 真实案例走查）

1. UA1：公开号抽取单测（中英文 OA 样本、误匹配负例）；手贴优先去重用例；冷却命中 ⇒ 零出网 + `reason_code=cooldown`（离线可证形态，沿 M-B §6 MB2 判据）；
2. UA2：模板锁用例——`reject_review` 生成 prompt 含复审请求书关键结构且**不含**意见陈述书开头模板；文末「提交前清单」段存在且为固定文案（不随 AI 输出漂移）；`first_exam` 模板逐字节不变（防回退）；
3. UA3：A33 用例——修改引入说明书外术语 ⇒ 结构化标记出现；纯删并权项 ⇒ 无误报；
4. UA4：截断处置用例（5000 档行为变更的对账说明）；
5. UA5：六角度骨架用例——deep 档 `reject_review` 分析输出含六个固定标题节（缺任一节即失败）；浅档与 `first_exam`/`abnormal` 不强制六节（防误伤既有行为）；
6. UA6：出处锚点用例——deep 档输出含「出处对照表」节；构造"材料中无出处的诱导断言"用例 ⇒ 断言被删除或标【需申请人确认】，**不得原样写入**；锚点段号指向不存在的段 ⇒ 判失败；
7. **真实案例走查**：用户真实驳回决定跑通 分析 → 讨论 → 生成，产物由用户人工核对（这是最终验收，规划会话参与核对）。会话内直接协助用户起草的**作业规程**已单独成文：`docs/plan/2026-10-01-oa-reexam-gold-standard.md`——软件验收以「能否复现该规程的六角度产出与出处锚点」为对照物。
