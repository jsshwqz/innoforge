# 创研台 InnoForge 产品核心愿景与永久业务宪章（Product Vision）

> **文件位置**：`docs/plans/product-vision.md`（同步由根目录 `AGENTS.md`、`CLAUDE.md` 及 `src/context.rs` 强制引用注入）
> **最高效力说明**：本文档定义了创研台（InnoForge）不可动摇的产品灵魂与研发者业务边界。任何 AI Agent 或贡献者在规划、重构、新增或裁剪功能前必须首先读取本文档，**严禁将本项目窄化理解成“纯专利检索软件”或“代理人写稿工具”**。

## §1 本质定位：技术开发者的全谱系创新锻造台

很多研发投入不是死在代码或样机实现阶段，而是死在更早之前或转化途中：想法看似可行却漏查了顶刊论文或专利壁垒；单靠打字描述不清复杂结构与实验现象；老产品专利正在应对审查意见（OA），新一代产品和实验又在并行推进；好不容易做出成果，却还要在产品立项书、调研报告、期刊论文与专利交底之间从头重复整理，甚至因“先发了论文后交专利”自己毁掉自己的新颖性。

**创研台（InnoForge）面向一线技术开发者、工程师与科研实战人员**（而非专职专利代理师），旨在把最初的技术念头逐步锤炼为**可核验的决策依据、实验验证方案、产品工程落地、学术论文/期刊发表以及知识产权保护（专利布局 / OA 与审稿抗辩）**，在单机绝对私密的前提下打通从灵感到全谱系成果的完整闭环。

## §2 六大永久业务与架构公理（AI 协作必读，永不重复解释）

后续所有架构设计与功能迭代必须无条件满足以下六条真实研发公理：

1. **表层每张卡片独立自治公理（Loose-Coupled Cards, Shared Vault）**

   * 首页每一张功能卡片（全域检索、多模态共创推演、单篇深析、多方案对决、审查与审稿抗辩、全谱系成果锻造、配置与知识金库）必须保持**100% 独立自治、即点即用、互不捆绑前置流程**。

   * 严禁强迫用户先创建重型项目容器才能使用单点工具；卡片之间通过底层的本机知识与证据金库（SQLite Vault）实现按需一键调取与知识复利沉淀。

2. **存量资产与增量研发双线并行公理（Parallel Portfolio & R&D）**

   * 真实研发并非从零真空起步，而是「我方先前已有专利/已发论文/在办 OA」与「新想法、新产品开发及实验验证」高度并行。

   * 系统必须支持将本地“我方已有成果”作为并行参考基线按需挂载，自动剥离增量创新特征，提供对照实验回填闭环，并防范自我公开或抵触申请风险。

3. **四维全域情报检索公理（Omni-Source Retrieval）**

   * 从新想法查起，检索视野**绝不局限于专利库**（专利存在 18 个月公开盲期且常隐藏实验细节）。

   * 底层检索必须全面覆盖四大圈层：**① 全球专利文献**（查权利壁垒）+ **② 学术期刊与会议/预印本论文**（OpenAlex / Crossref / arXiv / Semantic Scholar 等，查最新前沿机理与实验 Baseline）+ **③ 开源代码与工程方案**（查现成轮子与开源协议风险）+ **④ 行业标准、白皮书与竞品规格**。

4. **多模态复合输入与多轮共创公理（Multimodal Iterative Co-Creation）**

   * 技术构想绝不是靠一个单次纯文本输入框就能说清楚的，好方案是在多轮追问碰撞中定型的。

   * 想法沟通与技术问答必须原生支持**多轮启发式交互 + 复合模态输入**（包括直接粘贴剪贴板截图、手绘结构草图、CAD/电路原理图、实验曲线截图，以及拖入参考论文/旧专利 PDF、DOCX、代码或 CSV 实验数据表），聊透收敛为结构化方案基线后再进入深度自动化推演。

5. **审查与审稿三栖抗辩公理（Universal Evidence-Anchored Rebuttal）**

   * 项目沉淀的“原文锚点核查 + 严禁编造 + 逻辑链抗辩”内核（`evidence_kernel`），绝不仅限于已有老专利回官方 OA，必须一核三用：

     * **已有专利官方 OA / 复审答复**：应对审查员通知书，完成三步法争辩与不超范围权利要求修改；

     * **新专利提交前“魔鬼审查员”模拟预审**：在申请文件锁死前，用最强现有专利与期刊论文（NPL）做驳回压力测试，提前补齐权项漏洞与实验效果；

     * **学术论文/期刊模拟同行评审与返修回复（Response to Reviewers / Rebuttal）**：投稿前模拟审稿人挑刺（创新性、消融实验、漏引文献）；返修期逐条拆解 Reviewer 意见，绑定正文页码/图表/补充实验锚点生成回复信与修订留痕稿。

6. **一源四出成果锻造与公开时序守卫公理（Multi-Deliverable Forge & Priority Guard）**

   * 同一套经过求证与实验验证的技术内核，出成果必须覆盖四大体裁：**① 产品立项与工程设计规范（PRD/TRD）**、**② 全域技术调研与侵权风险（FTO）报告**、**③ 学术论文与期刊手稿（仅允许绑定真实核验过的 DOI/BibTeX 文献）**、**④ 专利技术交底书与 OA 答复三件套**。

   * **公开时序红线守卫**：当同一技术点同时筹备“论文/预印本/开源”与“专利申请”时，必须强制执行“先完成专利递交锁定申请日，后公开论文或代码”的冲突提醒，并按体裁自动做披露颗粒度与商业秘密（Know-how）裁剪。

## §3 最高实效验收口径（报告敢用 · 决策敢做 · 答复与成果敢交）

严禁以“代码行数、测试条数、PR 数量或文档字数”冒充研发进度。一切功能与重构的唯一验收标尺为：

1. **报告敢用**：调研报告、深析结论与对比矩阵中的每一处专利段落号、附图部件标号、论文 DOI 及实验指标均经确定性代码核验真实存在，零幻觉引用。

2. **决策敢做**：新想法经过四维情报穿透、矛盾分析与对照实验验证后，能清晰回答“真有增量创新吗、工程死结在哪、踩没踩他人专利雷、该投资源做产品还是先补实验”。

3. **答复与成果敢交**：产出的专利交底书、OA 答复三件套、期刊论文初稿、审稿人逐条回复信（Rebuttal）及产品立项规范逻辑自洽、修改不超范围、格式规范，经人工快速复核后可直接用于正式提交。

## §4 仓库落地与 AI 自动记忆机制（确保永久生效）

为保证在本地客户端（如 AionUI、Claude Code、Cursor）及云端协作中永远无需重复口述上述理念，本宪章通过三道机制焊死在仓库内：

1. **规约顶层绑定**：`AGENTS.md` 与 `CLAUDE.md` 开篇直接内嵌 §2 六大公理摘要，并指向本文档作为功能边界唯一权威源；

2. **运行时上下文自动注入**：`src/context.rs` 将六大公理纳入高优先级常驻上下文摘要，确保所有开发与分析会话默认感知全谱系创研定位；

3. **静态守卫防误删**：由集成测试守卫检查本文档与 `AGENTS.md` 核心公理标记存在性，防止后续维护中被意外覆盖或退化回窄化描述。
