# InnoForge 产品愿景与能力蓝图（创研台的真正用意）

> 2026-08-15 规划会话编制。地位：prd-v1.md 的上位文件——PRD 回答"修什么"，本文回答"为了成为什么"。

## 1. 产品身份宣言

**创研台 = 发明人身边常驻的虚拟 IP 专家团队。**

它服务的不是一个"搜索请求"，而是发明人的完整决策链：

> 我有个技术点子 → 全世界有人做过吗？→ 我的点子新在哪？值不值得申请？→ 往哪个方向改？权利要求怎么布局？→ 提交后收到审查意见怎么办？

这条链上，现实中的发明人需要雇**检索员、技术分析师、专利代理师**三个角色。创研台要把这三个角色装进一台本地机器——而且每个角色的产出都必须**可核验、有出处、不糊弄**，因为发明人要拿这些结论去赌真金白银的申请费和两年等待期。

## 3. 北极星（产品级验收）

> **一位发明人，只靠创研台，完成一次"点子 → 验证报告 → 申请决定"，并在收到 OA 后产出可直接提交的意见陈述书——全程不需要开第二个工具来交叉核对。**

拆成三条可测判据（并入各里程碑验收）：

1. **报告敢用**：验证报告的每条事实结论带出处，发明人抽查不出编造（MB6 的 10 条 ≥9 条有源只是下限，终态是抽查不出错）
2. **决策敢做**：报告末尾的建议段明确回答"申请/放弃/转向"+ 三条理由，且理由能在报告内自洽溯源（⑤的到位标准）
3. **答复敢交**：DOCX 导出的意见陈述书，发明人只需复核不需重写（⑧）

## 4. 里程碑在旅程中的位置

```
M-A 可信中文检索     → 治 ②（侦察兵上岗）
M-B 可信深度分析     → 治 ③④⑤⑥（分析师+防线+决策依据）
M-C 全流程贯通       → 把 ②③④⑤⑥⑧ 缝成一条路 + 交付最后一公里
后续候选（本次不做）：⑦ 实验沙箱激活、决策建议专用模型调优
```

## 5. 给执行 agent 的解读规则

- task-breakdown 里任何任务的验收标准，遇到歧义时**以本文对应旅程段的"到位标准"为解释基准**
- 功能取舍冲突时，问一句："这更接近哪个角色（检索员/分析师/代理师）的本职？"——偏离三个角色本职的炫技需求一律砍掉
- 本地利器形态不变：所有能力单机可用，不引入云依赖（除既有外部 API）
