## 一、任务概述

P4-T2：多轮答复全流程追踪。为 InnoForge 增加 OA（审查意见）多轮答复的完整追踪能力，让研发用户能记录、查看和管理一件专利从一审到最终授权/驳回的每一轮 OA 审查与答复。

任务规格见：`docs/plans/2026-10-03-phase4-task-assignment.md` 中的 P4-T2 部分。

## 二、已完成工作

### 2.1 数据库迁移（v23 → v24）

- 文件：`src/db/migrations.rs`
- 新建 `oa_rounds` 表，字段：
  ```
  id TEXT PRIMARY KEY
  patent_id TEXT NOT NULL
  round_number INTEGER NOT NULL
  round_type TEXT          -- first_rejection / second_rejection / reexamination / office_action
  oa_date TEXT             -- 审查意见发文日期
  oa_text TEXT             -- 审查意见正文
  response_date TEXT       -- 答复日期
  response_text TEXT       -- 答复正文
  result TEXT              -- accepted / rejected / partially_accepted / NULL(待处理)
  result_date TEXT         -- 结果通知日期
  strategy_used TEXT       -- 使用的答复策略
  quality_score REAL       -- 答复质量评分
  notes TEXT               -- 备注
  created_at INTEGER
  updated_at INTEGER
  ```
- `src/db/mod.rs`：`SCHEMA_VERSION` 从 22 改为 24（注意：之前 v23 迁移已存在但版本号未更新，本次一并修正为 24）

### 2.2 后端 DB 层

### 2.3 后端路由层

- **新文件**：`src/routes/oa_rounds.rs`（251 行）
- 5 个 handler：

| 方法 | 路径 | handler | 功能 |
|---|---|---|---|
| POST | `/api/oa/rounds` | `api_oa_rounds_create` | 创建新轮次 |

| GET | `/api/oa/timeline/:patent_id` | `api_oa_rounds_timeline` | 时间线视图（含汇总统计） |

- ID 生成：`chrono::Utc::now().timestamp_millis()` 转字符串
- 路由注册：`src/routes/mod.rs` 添加 `mod oa_rounds;` + `pub use oa_rounds::*;`
- `src/common.rs` 添加 `put` 到 routing import，注册 4 条路由（DELETE 路由也在其中）

## 五、技术注意事项

### 5.1 SCHEMA_VERSION 跳变说明
- 之前 `SCHEMA_VERSION` 是 22，但 migrations.rs 中已有 v23 迁移代码
- 本次新增 v24 迁移，同时将 `SCHEMA_VERSION` 直接设为 24
- 这意味着 v23 的迁移代码会执行，v24 的也会执行
- 如果其他 AI 的分支也有 schema 版本变更，merge 时需要协调版本号

### 5.2 `pub mod oa` 可见性变更
- `src/db/mod.rs` 中 `mod oa;` 改为 `pub mod oa;`
- 原因：`src/routes/oa_rounds.rs` 需要引用 `db::oa::OaRound` 类型
- 如果其他模块也需要访问 oa 模块的类型，这个改动是兼容的

### 5.3 `showTab` 函数重写
- 在 `patent_detail.html` 中重写了 `showTab` 函数（包装原始函数 + 加载 OA 时间线）
- 如果其他 AI 也修改了 `showTab`，merge 时会冲突
- 解决方案：在合并后的版本中，确保 `showTab` 同时处理所有需要懒加载的标签

### 5.4 `escapeHtml` 函数重复
- `patent_detail.html` 和 `office_action_response.html` 各自定义了 `escapeHtml` / `escapeHtmlOa`
- 如果页面已有同名函数，不会报错但会覆盖
- 建议后续统一到 `static/i18n.js` 或公共 JS 文件

### 5.5 分支上的额外 commit
- `feat/oa-workflow-tracker` 分支上除了 T5 的 commit（`4a7fbe8`），还有从 main 继承的历史 commit
- 这些是 main 上的其他 AI 工作（T3 交接文档等），不是 T5 的改动
- merge 时只需关注 `4a7fbe8` 这个 commit
