## 2. 现状实测（真 / 半 / 空）

**真有（可用的工程底座）**

- 16 步 pipeline、4 源检索链、快照续跑、分层报告（executive/technical）、成本落账 21 点、profile/记忆、按钮回归 CI、迁移锁（#60 修复）、#70 空检索不冒充满分、#72/#73 修复。

- feature cards CRUD + 卡片间最小差异；evidence_chain 表；RAG 已接进 analysis 步骤（`analysis.rs:394`）。

**半成品**

- 向量检索：9/28 拍板 B 案，是本地 n-gram 相似度，不是语义；`/api/search/vector` 存在，但前端无入口（`templates/` 无调用）——功能不可达。
- 报告：原始规划的三类输出（领导版/研发版/**专利版**）缺专利版。
- 规避设计、问题拆解、V-RAG、引证图谱：只在 prompt 里出现，没有结构化能力。
- **OA 主链路输入预算过小**：`src/ai/patent.rs:307-308` 把本专利与对比文件各截到 **5000 字**；`truncate_for_ai`（`src/ai/client.rs:284`）会显式追加"材料不完整、禁止推测"的提示（草案初稿说"无显式标记"有误，已按 DS 复核更正），但 5000 字的预算客观压低了"可提交度"——单篇对比文件的权利要求就可能超过这个数。
- **事实核查门存在放行漏洞**：`ai/fact_check.rs` 的"致命"每条只扣 35 分，两条致命仍得 70 分，而门限是 `score <= 65`（`routes/ai.rs:1889`）——两条致命仍放行；`pipeline/steps/finalize.rs:30` 对 `fact_check_rejected` 只 `warn`，不阻断。

**没验（最关键的空白）**

- **真实模型下的输出质量**：上一轮真实案件冒烟用本地 mock 模型，只能证明"管线通"，不能证明"报告能用"。
- 上次实测的 DeepSeek key 返回 401。本机 8080 网关已在本轮重新拉起并实测通过（`claude-sonnet-4-6`，HTTP 200，2.19s，54 tokens；可用模型含 `claude-opus-4-6-thinking` / `gemini-3.8-flash-high` 等，零边际成本）。
- 因此到现在为止，**没有任何一份真实模型生成的报告被按"能否直接用于决策/提交"评过分**——这是 M1 要补的第一课。

## 3. 漂移的四条机制

1. **目标被指标替换（Goodhart）**：CI 绿、issue 关闭数、文档覆盖率、测试数量成了周报内容；"这份报告能不能用"没有度量，于是不在视野里。
2. **难度选择偏置**：小修可证明、可关门、可写负控；质量评估需要真模型、需要专业判断、难以自动化，于是被一轮轮推迟。每轮都"完成了"，产品却没有更可用。
3. **双线失联**：云端 DS 按 #90 排 #78（检索基础设施），本地 ZCode 做 #125（证据内核），两条线都正确，但不在同一目标上；#125 又明确不覆盖 OA 主链路——真实用户恰恰在 OA 链路工作。
4. **计划通胀**：三套优先级 + 137KB STATUS + 三份路线图；每轮读文档与登记的成本超过做产品的时间，越慢越记、越记越慢。

## 4. 再对齐主张

### 北极星（未来三周唯一）

> **一宗真实在办的 OA/复审案 → 答复书 + 证据表 → 人工判"可提交"。**

产品级验收以 `docs/plan/product-vision.md` §3 的三条为准：

1. **报告敢用**：每条事实结论带出处，发明人抽查不出编造。
2. **决策敢做**：建议段明确回答"申请/放弃/转向"+ 三条理由，理由能在报告内自洽溯源。
3. **答复敢交**：导出的意见陈述书，发明人只需复核、不需重写。

本切片只承诺第 1、3 条（OA 答复书 + 证据表）；第 2 条在报告建议段一并核验。不选 idea/查新链路作为第一验收面：那会滑回"管线工程验收"，而真实用户当前在 OA 链路工作（DS 复核）。

五维 rubric（上述三条的评分细化，每项 1–5 分）：

1. **事实准确**：每条事实断言都能回到原文；无编造。
2. **法条与逻辑**：引用条款正确，三步法/驳回理由的回应成立。
3. **覆盖**：对比文件、权利要求、审查意见要点无遗漏。
4. **可追溯**：引用锚点核验通过率；伪造锚点必须被抓出并降级。
5. **可直接提交度**：人工通读后"只需小改"还是"必须重写"。
